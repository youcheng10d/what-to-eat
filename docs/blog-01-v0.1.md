# 今天吃啥 · 开发日志 01

v0.1 · 从一句 Prompt 到第一个上线项目 · What to Eat

> 说一句偏好，替你把「今天吃啥」这顿定了。

项目英文名 What to Eat（仓库 what-to-eat，下文简称 wte）。正式中文名还在构思中，之后会与多个 AI 一起讨论选定，暂以「今天吃啥」相称。本文是 wte 开发日志系列的第一篇，记录它如何从一句 Prompt 变成我的第一个上线项目。

---

## 为什么做这个

「今天吃什么」大概是大学生每天回答次数最多、也最难回答的问题：档口几十个、菜品几百道，预算、口味、减肥计划全要在排队的三分钟里做完决策——多数时候干脆随便吃，吃完又后悔。

正好赶上传智杯 · 全国高校 Vibe Coding 开发挑战赛（我选了方向⑥：校园/垂直社区全栈 MVP 平台），决定把这个问题做成自己第一个真正意义上的项目：不是为比赛临时拼一个 demo，而是从一个真实痛点出发，认真做、持续迭代，也作为求职作品集的起点。

---

## 起点：一段原始 Prompt

Vibe Coding 的核心不是「让 AI 随便写」，而是把意图对齐做在前面。wte 的第一行代码来自这段 Prompt（原文保留，一字未改）：

> 作为一个前端工程师，请帮我创建一个"今天吃啥"的移动端风格 Web 应用。要求：
> 1. 页面简洁美观，有食欲感。
> 2. 顶部有一个输入框，用户可以输入自己的饮食偏好（如：减肥、预算15元、不想吃辣）。
> 3. 下方有一个显眼的"替我决定！"按钮。
> 4. 点击按钮后，从模拟的 50 道大学食堂菜品数据中，智能筛选并推荐一个菜品，并以卡片形式展示菜品名、价格、卡路里和推荐理由。

回头看，这段 Prompt 里有两个决定性的细节：

- 明确了输入形态——自然语言偏好，而不是表单勾选；
- 明确了输出字段——菜名、价格、卡路里、推荐理由。

后来的数据模型和推荐引擎，都是围绕这两点长出来的。

---

## 三个关键设计决策

### 数据模型为推荐引擎服务

50 道菜不是随便列的清单。每道菜都带一组为「偏好匹配」设计的字段：口味标签、辣度分级（0–3）、是否素食、卡路里、价格，以及人气、低卡、性价比这类运营标签。「减肥」能不能命中低卡菜、「不想吃辣」能不能过滤干净，取决于字段设计得够不够细。

### 硬过滤 → 诚实放宽 → 加权随机

解析层用正则和关键词把「预算15元」「减肥」「不想吃辣」拆成结构化条件；硬过滤层先严格执行；如果筛完为空，按热量 → 预算 → 素食 → 忌辣的顺序逐级放宽，并明确告诉你放宽了哪条——宁可承认条件苛刻，也不静默塞一个不符的菜。最后软打分（命中偏好加分）取 top5 加权随机，在「懂你」和「不重样」之间找平衡。

### 食欲感是第一生产力

一个帮你「决定吃什么」的工具，页面本身得让人饿。v0.1 用暖橙奶油色系打底，AI 生成的食堂质感插画做视觉锚点，楷体大标题压住气质，卡片出场和菜名轮换动效控制节奏；整体按移动端 430px 单列设计，并尊重系统的「减弱动态效果」偏好。

---

## 工程结构：零依赖，但留了后门

- 纯静态：HTML + CSS + 原生 JavaScript，5 个文件，零框架、零构建工具，双击 index.html 即可运行，任何人 clone 下来都能零成本复现。
- 服务层 api.js：推荐服务单独成层，接口形状（入参 preferences，返回 dish / matched / reason / relaxed）完全按真实后端的标准设计，内部实现暂时是本地计算，代码里留了 TODO 替换点——将来接后端时，前端其他文件一行不用动。
- 两处细节：偏好草稿存 localStorage，刷新不丢；「换一个」通过 excludeIds 排除已推荐过的菜品。

---

## v0.1 的诚实局限

- 50 道菜全是模拟数据，卡路里按品类估算，不是真实营养值；
- 没有真实档口信息，推荐无法回答「去哪个食堂哪个窗口」；
- 纯前端，数据更新靠改代码。

## 写在最后：1% 的灵感与 99% 的汗水

爱迪生说：「天才是 99% 的汗水加上 1% 的灵感。」做一个产品也是一样——把 wte 从一句 Prompt 做成一个上线的项目，就是一次小小的「从零到一」：灵感负责回答「做什么、为什么做」，汗水负责把想法一步一步变成能跑的代码、能用的产品。缺少任何一半，这个项目都不会存在。

在 AI 时代，这句话有了新的注解。这个项目里，大量的实现工作都有 AI 参与——写代码的门槛正在被 AI 快速拉低。这意味着那 1% 的灵感变得格外重要：看见「大学生每天为吃什么纠结」这个真实痛点的眼睛，判断产品该站在消费者一边还是经营者一边的头脑，在每一个设计岔路口做出取舍的勇气——这些是 AI 给不了的。AI 可以帮你写出推荐引擎，但不会替你发现值得解决的问题。

但反过来，光有这 1% 的灵感，同样不足以让一个产品实现从零到一、再走到落地。从「要是有个工具能替我决定吃什么就好了」这个念头，到真正能打开就用的 v0.1，中间隔着数据模型的一次次推敲、放宽策略的边界取舍、动效细节的反复调试——灵感是种子，执行力才是让它发芽的土壤。

所以我想把这句话作为这个系列的注脚：在人人都有 AI 的今天，愿意为了那 1% 的灵感，付出 99% 的执行力，反而成了最稀缺、也最可贵的事。wte 不会停在 v0.1——灵感已经落地成第一版，接下来的每一版，都会是汗水的续篇。下一篇，讲讲我是怎么把学校食堂几百道真实菜品搬进这个纯前端的。
