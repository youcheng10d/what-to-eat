# 吃嘛 v2.1 开发手记：当用户说"不吃面"，系统为什么还在推面？

> 标题候选（发布时选一个）：
> 1. 「不吃面」三个字，我们的推荐引擎翻车了三次
> 2. 从用户实测"面食太多"说起：食堂推荐引擎 v2.1 修复手记
> 3. 1143 道菜里藏着 46.7% 的面食——推荐系统的数据真相与修复

---

## 一、起因：用户的三个"差评"

吃嘛（What to Eat）是一个纯前端的食堂菜品推荐应用：输入一句话（"想吃辣的，预算 15 元"）或勾选口味档案，系统从 1143 道菜里抽三张卡。

v2.0 上线后，我和同学多轮测试，收到三个扎心的反馈：

1. **三卡模式面食出现概率太高**——不管开不开口味档案都这样；
2. **口味档案一确认，推荐就像被"锁死"**——勾了"辣+咸鲜"之后，出来的一水儿辣菜；
3. **输入"不吃面"，系统反手推三张面**——它把"不吃面"里的"面"当成了"想吃面"。

还有一个我自己提的需求：**档案里能直接填"不喜欢吃的档口"**，比如"兰州拉面"，之后推荐永远绕开它。

这篇文章记录 v2.1 怎么把这四个问题一个一个拆开、修掉，以及我们怎么在没有测试框架的纯前端项目里搭起五层测试防线。

## 二、先看数据：问题不全是代码的锅

修复之前，我先跑了一遍数据统计，结果有点震惊：

- 全库菜品 **1143 道**，其中**面食 534 道，占 46.7%**；
- 单一个"外公家米线"档口就有 **212 道菜，占全库 18.5%**；
- 价格 ≤15 元的菜 1031 道——食堂定价就是这么朴实。

也就是说：**哪怕引擎完全公平、按菜品等概率随机抽，面食天然就该占一半**。但 46.7% 的数据占比，不该被放大成 80% 的观感。真正的 bug 藏在抽样算法里。

## 三、Bug 1：按"菜品"抽签，菜多的档口自然赢麻了

旧版打分后按全库菜品加权抽样（softmax）。问题在于：抽的是"菜品"，不是"档口"。外公家米线一家 212 道菜，每道都参与抽签，相当于这个档口有 212 张彩票，其他小档口只有几张。实测结果就是它**经常霸榜**，"面食太多"的观感主要来自它（还有菜普遍比较多的面食档口群）。

**v2.1 方案：档口分层两段抽样**

```
第一段：按档口聚合，每个档口以"档内最高分"为代表，再乘品类规模系数（1/√品类菜品数）
第二段：选中档口之后，再在档内按分数抽具体菜品
```

- 每个档口只占一个签位，212 道菜的大档口不再有 212 次机会；
- `1/√菜品数` 的品类系数温和压制面食这种"品类人口大国"，但保留人气菜的优势；
- 第一段按"档内最高分"而非平均分，是对"档口有拿手菜"的合理倾斜。

修复后实测（真实数据、各组 12 次）：

| 场景 | 修复前面食率 | 修复后面食率 |
|---|---|---|
| 无档案·三卡 | 33% | **22%** |
| 无档案·单卡 | 42% | **17%** |
| 辣+咸鲜档案·三卡 | 53% | **33%** |
| 清淡档案·三卡 | 58% | **39%** |

外公家米线：**18.5% → 2%**。后两行仍偏高不是 bug，是"口味与数据的交集"：数据里"辣味菜""清淡菜"本身就是面食居多，属于合理的口味导向。

## 四、Bug 2：档案口味权重为什么"锁死"了推荐

旧版打分：每命中一项档案口味 **+8**，无限叠加。勾"辣+咸鲜"两道菜能叠出 +16，在 softmax 里直接把其他菜挤出决赛圈。实测辣档口垄断到 83%。

**v2.1 方案**：
- 口味命中改为 **+5/项，封顶 +12**；
- 荤素倾向（想吃肉/想吃素）从 +12 降到 **+7**；
- 保留导向性，把空间还给随机性。

效果：辣档案的辣占比 **83% → 67%**，12 轮三卡的档口多样性从 13 个升到 18 个。用户能感觉到"系统记得我的口味，但没有被我绑架"。

## 五、Bug 3：「不吃面」是怎么被当成「想吃面」的

这是最打脸的一个 bug，修复过程也最能说明"自然语言不等于关键词匹配"。

### 5.1 第一次修复（v2.1 初期）

原来面食意图检测直接跑在原句上：

```js
// 旧代码（有 bug）
if (/面|饺子|米线|.../.test(s)) p.preferCat.push("面食");
```

"不吃面"里的"面"字直接命中，系统美滋滋地认为你想吃面。

修复思路是**否定掩码**：先把句中所有否定片段（"不吃/不想/不要/别…"及其宾语）用等长空格掩掉，正向意图只在掩过的句子上检测；再用一条否定正则在原句上识别"明确否定面食"，把整个面食品类拉进排除名单。

### 5.2 第二次修复：数据里藏着 32 道"假非面食"

修完一测，逻辑都对了——但线上实测**还是能抽出面**。查数据发现：有 **32 道名字里带面/粉的菜，品类标签根本不在"面食"下**：

- 盖浇饭类 27 道："咖喱鸡拌饭/面/粉"、"番茄鸡蛋盖浇面/饭"、"葱爆牛肉盖浇面/饭"……
- 家常小炒 3 套"火鸡面套餐"、1 道"肉沫粉丝"；
- 早餐小吃 1 道"香辣粉丝包"。

之前按 `category === "面食"` 排除，这 32 道自然全部漏网。

**v2.1 最终方案：面类制品判定 = 品类 OR 名字**

```js
const NOODLE_NAME = /(?:面|粉|米线|饺子|水饺|抄手|馄饨|拉面|刀削|河粉|粉丝|螺蛳粉|挂面|意面)/;
const isNoodleLike = (d) => d.category === "面食" || NOODLE_NAME.test(d.name || "");
```

"不吃面"在硬过滤层把这道判定全部拦下。100 轮三卡（300 张）实测：泄漏 **0 张**。

### 5.3 第三次扩展：从"不吃面"到"不吃任何东西"

检查时发现一个问题："不吃水饺"是**完全无效**的——"水饺"不含"面/米线/饺子"这些词，旧正则什么都匹配不上；更别说"不要葱""不吃土豆"这类诉求，全被否定掩码吞掉后毫无效果。

于是我把它抽象成一条**通用否定宾语提取**规则，覆盖用户"今天只是想除了这个之外的其他菜"的完整语义：

| 输入 | 行为 |
|---|---|
| 不吃面 / 不吃粉 / 不吃米线 | 面类制品整体排除 |
| 不吃水饺 / 不吃饺子 | 水饺全排除（"饺子"自动映射"水饺"两个字） |
| 不吃肉 | 只推素菜 |
| 不要葱 / 不吃土豆 / 不喜欢吃鸡 | 含这些材料的菜关键词排除 |
| 不吃辣 | 忌辣硬过滤（与"后写优先"的冲突裁决兼容） |

一个细节：数据里的饺子菜叫"水饺"，不含"饺子"二字。如果只把"饺子"当关键词，会一个都匹配不上——所以"饺子"这个词要展开成 `["饺子", "水饺"]` 两个关键词。

## 六、档案避雷：直接填档口名

档案里的忌口输入框现在支持填档口名（"兰州拉面"、"胖妹面庄"），按顿号/逗号/空格拆分后，匹配范围从菜名描述扩展到**档口名**，命中即整档排除。

顺带修了一个隐蔽冲突：原来档案忌口会**覆盖**输入框里的文本忌口（文本说"不吃香菜"、档案填了"兰州拉面"，香菜就丢了）。现在两条合并去重。

"试试新的！"按钮走不走这套逻辑？走。因为硬过滤在打分之前执行，对单卡/三卡/新档口三条路径统一生效——集成测试里专门用 8 轮"普通/试试新的"交替验证过。

## 七、没有测试框架，怎么搭五层防线？

纯前端项目，没引任何测试框架。我们的做法是：Node 直接用 `vm.runInNewContext` 加载同一个 api.js，配一个 `window` shim，然后裸写断言脚本，靠 `process.exit(1)` 报错。五层：

1. **冒烟测试**：真实数据能加载（1143 菜 / 49 档口）、字段无缺失、价格热量区间合理、id 唯一、API 和卡片结构完整；
2. **单元回归**：mock 小数据集验证每条规则——轻食意图、荤素冲突、预算、忌辣、override、不吃面、来碗面、不吃水饺、档口避雷；
3. **集成测试**：真实数据跑完整流程——面食率 <30%、外公家 <12%、"不吃面/水饺/葱/土豆"各 100~200 轮零泄漏、12 轮三卡档口多样性、今天吃过排除与撤销；
4. **金文件测试**：用自己写的 LCG 替换 `Math.random` 固定随机种子，把 6 个场景的推荐结果快照成 JSON。CI 上只比对、不重新生成，保证"改引擎必须人肉确认输出变化"；
5. **变异测试**：把 api.js 源码字符串替换注入 10 个典型缺陷（删掉面类过滤、否定提取失效、预算放宽 5 元、忌辣阈值改成 99、画像权重翻倍、档口分层退化……），跑同一套断言，每个缺陷都必须被"杀死"。当前 **10/10 全部杀死，杀死率 100%**。

全部测试已接入 GitHub Actions，push 即跑。

测试里最有意思的坑是**概率断言的稳定性**：面食率这种统计断言，取样 20 次时波动有 ±10%，阈值定得再好也会偶发假失败。我们最后用"实测分位数定阈值 + 加大取样量"（如面食/变异断言取样 200~300 次）把假失败压到最低。

## 九、写在最后

这次 v2.1 给我的最大教训是：**推荐引擎的 bug 很少住在代码的显眼处，更多住在数据里**。"面食概率太高"表面是抽样问题，背后是 46.7% 的数据分布；"不吃面还推面"表面是正则问题，背后是 32 道挂错品类的菜。修引擎之前，先问数据要真相。
