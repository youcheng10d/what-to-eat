# AI 协作与开发演进记录

> 赛题要求「开发全链路可被完整重现」。这份文件是证据链：每一次迭代，人提出了什么、AI 产出了什么、人又改了什么、最后怎么验收的。

## 0. 协作方式

一句话：**人定规则，AI 写实现，验收靠测试。**

| 角色 | 负责 |
| --- | --- |
| 人（作者） | 定义问题、定架构与边界、判断什么算「对」、写验收用例、决定取舍 |
| AI | 写代码、写数据清洗脚本、写文案、生成测试、解释报错 |

这条边界不是客套。本项目的三次重大返工（见第 4 节）全部由人发现「结果不对」，AI 只负责定位与修复。

## 1. 迭代 A｜推荐引擎：从「条件满足」到「说人话」

### 1.1 意图

初版引擎只会做过滤：预算、热量、忌辣、荤素，满足即出。真实使用后暴露三个问题：

1. 同时说「想吃肉」和「不吃肉」时，前者被静默丢弃；
2. 「不吃面」会被解析成「想吃面」，因为「面」字命中了正向词表；
3. 无解时直接回落到全库随机，用户看到的是「说了等于没说」。

### 1.2 关键 Prompt（节选）

> 用户会一句话里同时说想吃和不吃，比如「想吃肉但又不想吃肉」。不要静默丢掉任何一个，也不要报错。请按「后写的优先」裁决，并把裁决结果用人话讲给用户听。另外，否定片段不能被正向词表误命中——「不能吃辣」里的「能吃辣」不算想吃辣。

> 无解时不要直接随机。按「热量 → 荤素 → 预算 → 忌辣 → 忌口」的顺序逐级放宽，每放宽一项都要在卡片上明确告诉用户放宽了什么。宁可告诉他「放宽了预算」，也不要假装匹配成功。

> 三卡模式一次给三个不同档口，但要注意最近 10 张卡里同一个档口不能反复出现。请实现一个滑动窗口，而不是简单的「本次不重复」。

### 1.3 AI 产出与人的修改

| AI 给的 | 人改的 | 原因 |
| --- | --- | --- |
| 用 `masked` 掩码句做正向匹配 | 保留，但要求掩码长度与原句对齐 | 不对齐会导致索引错位，冲突裁决取不到正确位置 |
| 逐级放宽用一个 `while` 循环 | 改为固定顺序表 + `droppedKeys` 集合 | 顺序必须可预测，否则同类输入可能放宽不同项 |
| 三卡滑窗按「本次请求」计数 | 改为把已发出的卡先并入窗口再判 | 否则三卡按旧窗口连判三次，10 张里只剩 2 张换口味 |

### 1.4 验收

`tests/recommend.test.mjs` 与 `tests/integration.test.mjs`：

- 「不吃面」8 轮三卡不推任何面类制品（含跨品类挂靠的 32 道）
- 「不吃水饺」200 轮不推相关菜
- 「不能吃辣」8 轮不推辣菜
- 12 轮三卡的档口数量 ≥ 8，任一档口占比 ≤ 35%
- 荤素冲突按后写执行，并提供「两种都看看」

## 2. 迭代 B｜口味槽位制：从「加分」到「轮转」

### 2.1 意图

v2.2 的口味是加分制：命中几个口味就加几分。用户勾了「辣 + 酸甜」之后，几乎每张卡都能命中至少一个，口味形同虚设，实测换口味的比例不到 15%。

### 2.2 关键 Prompt（节选）

> 现在的口味是「命中即加分」，多选时等于没选。请改成「每张卡先定一个主角口味」，只在这个口味里抽菜；多个口味按轮转分配。
>
> 另外要能「换个口味」：最近 10 张里如果换口味的卡不足 3 张，就该补一张。但探索卡必须是「纯净」的——不能同时带用户已选的口味，否则用户根本感知不到换了口味。
>
> 注意「麻」这个口味在库里没有单口味菜，永远和辣或酸甜绑定。已选辣时如果选「麻」探索，必然是假探索，要在选槽位阶段就排除。

### 2.3 人的修改

- AI 最初把探索配额做成「每次请求最多一张」，人发现三卡模式下仍然会漏，改成按窗口欠账计算；
- AI 最初用 `g[0].category` 估算档口主品类，人指出数据顺序不具代表性，改为按档口内品类计数取众数；
- AI 最初把「强反差」配额设为 2/10，人实测后压到 1/10——反差太频繁会让用户觉得「它不听我的」。

### 2.4 验收

`tests/flavor-matrix.mjs` 跑了 63 组口味组合，每组多轮：

- 换口味占比落在 25%–35%
- 任意 10 张强反差 ≤ 1 张
- 每个已选口味都轮到过
- 「酸甜」单口味：任意 10 张至少 2 张换口味

结果见 `docs/blog/blog-08-v2.3.2.md`。

## 3. 迭代 C｜AI 接入：把「估算」换成「算出来」

### 3.1 意图

评审意见有两条：一是赛道要求真的接入 AI，二是「卡路里不能是写死的」。

这里有一个容易做错的选择：让模型直接报一个热量数字。那是把「写死」换成了「模型瞎编」，评委一问就穿帮，而且同一道菜两次调用可能给出两个数。

最终定的架构是：**AI 只负责理解，不负责计算，也不负责挑选。**

> 营养拆解：模型只返回原料名与克数，不许返回热量；热量由前端用《中国食物成分表》逐项相乘求和，并把算式摊开给用户看。
>
> 这样做的原因：克数模型估得比人快，但乘法和加法不需要模型。算错一个乘法，整道菜就废了；而这个错误完全可以避免。

### 3.2 关键 Prompt（原文）

营养拆解的系统提示词（`ai-worker/index.js` 内，逐字）：

> 你是大学食堂的营养拆解助手。用户给你一道真实在售的菜品，你估算它的主要原料与可食部克数。
> 规则：
> 1. 只输出 JSON，不要任何解释。
> 2. 4-6 项原料，按克数从大到小排列。
> 3. 克数是「一份」的熟重，取 5 的倍数，整份总重控制在 200-600g。
> 4. name 必须是常见食材名（如 米饭、面条、猪五花、鸡蛋、番茄、食用油），不要写菜名，不要写品牌和调味料名。
> 5. 绝对不要输出热量数值——热量由系统用食物成分表计算，你只负责给克数。
> 输出格式：{"items":[{"name":"米饭","g":250}]}

罗盘（玄学模式）的系统提示词：

> 你在一个食堂点餐小游戏里扮演「解签人」。用户会说一句和吃饭有关、但通常很荒诞的话（例如「高数要挂了」「帮我看看手相」「转了三圈烟灭了」）。
> 你的任务不是推荐菜，而是把这句话翻译成一张签和一组可执行的筛选条件。
> ……
> 2. sign：一句 8-18 字的签文，像食堂窗口贴的纸条，要具体、有画面、带一点冷幽默。不要鸡汤，不要「愿你」。

拍照问诊的系统提示词，重点在约束边界：

> 2. 不做任何医疗诊断，不使用「患病」「炎症」「内分泌」「湿气」这类词。
> 3. 不评价美丑、胖瘦、年龄、性别、身份、穿着。
> 4. 只写照片里能看见的：皮肤状态、精神状态、是否出汗、是否戴眼镜。
> 7. 如果看不清人脸，observations 返回空数组。

### 3.3 人的修改

| AI 给的 | 人改的 | 原因 |
| --- | --- | --- |
| 把热量也放进模型返回的 JSON | 删掉，契约层禁止出现 `kcal` 字段 | 一旦允许，模型一定会编，而且两次调用不一致 |
| 让模型按标签直接给菜名 | 改成只给约束，抽哪道菜由 seed 在本地算 | 模型会编不存在的菜名；本地抽签可复现 |
| 拍照后自动套用饮食建议 | 改成把建议写进输入框，用户可改可删 | 决策权要留在人手里，这也是答辩时的加分点 |
| 罗盘每次随机 | 改成 `hash(原话 + 日期)` 决定落点 | 同一句话同一天结果固定，现场演示两遍结果一样，这才叫可复现 |

### 3.4 验收

- `ai-worker` 契约测试 12 条：预检 CORS、缺字段 400、未知路由 404、没配 Key 返回 502 而不是假装成功、返回体不含 `kcal`；
- 前端逻辑测试 25 条：食材匹配、别名、未收录不猜、热量求和、116 食材表、本地估算中位数 107%（70 道抽样）、罗盘确定性、标签映射；
- 端到端：用假 Worker 跑通「AI 拆解 → 绿色 AI 徽标 → 算式展开 → 未收录提示」，以及「拍照 → 标签 → 写回输入框 → 出卡」；
- 断网降级：无 Worker 时自动切本地规则估算，UI 明确标注「本地估算」，不会假装是 AI。

## 4. 三次由人发现、AI 定位的返工

这部分是「引导 AI 修 Bug」的原始记录，比成功案例更能说明协作方式。

### 4.1 卡片在转场时「冻住」1.5 秒

- 现象：视频 20–22 秒有明显卡顿。
- 人的判断：不是帧率问题，是某段时间画面根本没变。
- AI 定位：`text()` 与 `drawImageRounded()` 内部把 `ctx.globalAlpha` 直接赋值为自己的 `alpha`，覆盖了外层包裹的淡出值。结果外层把 alpha 设成 0，里层又设回 1，卡片一直停在原地。
- 修复：内部改为 `ctx.globalAlpha * alpha`。
- 教训：Canvas 的全局状态是隐式的，「谁最后写谁生效」。封装绘图函数时必须乘法叠加，不能覆盖。

### 4.2 收藏面板一打开就错位

- 现象：标题和列表并排出现，面板被截断。
- AI 定位：`.fav-panel` 是 `display:flex`，默认 `row`，标题和列表成了左右两栏。
- 修复：`flex-direction: column` + 子元素 `max-width` 对齐。
- 顺带发现：这个 bug 一直存在，只是因为之前没人打开过收藏面板。**为了拍视频去用它，才把它暴露出来。**

### 4.3 视频 02–03 秒的下划线反复横跳

- 现象：打字机效果时，下划线右端不规则跳动。
- AI 定位：下划线宽度是按「当前已打出的文字」实时 `measureText` 的，每多一个字宽度就跳一次。
- 修复：一次性测量完整句子宽度，让下划线从 0 匀速长到最终宽度。
- 教训：动画要基于「终点」而不是「当前状态」，否则会跟着中间状态抖。

### 4.4 称重菜品被当成一块九的菜

- 现象：麻辣烫卡片显示 `¥1.98`，用「预算 5 元」也能把它推出来。
- 定位：牌面写的是「1.98 元/50 克」，OCR 把每 50 克的单价当成了整份售价。数据层没有区分「单价」和「每份价」。
- 修复：构建期识别 `x 元/50 克` 文本，写入 `pricing:"weight"`、`unitPrice`、`unit`，并把 `price` 换算成按 400g 估的每份价；卡片上两者并列显示，注明「实际以称重结算」。
- 连带影响：两道菜移出 15 元预算候选池，金文件 `budget-meat` 的抽样序列整体移位。逐条人工核对新基准后执行 `--update`，9 条结果全部仍在预算内。
- 教训：**数据里混进错误单位，比没有数据更危险**——它不会报错，只会安静地把结论带偏。

## 5. 可复现命令

```bash
# 1. 直接运行（零依赖）
双击 what-to-eat/index.html

# 2. 重新构建数据（PowerShell）
powershell -File tools/build-data.ps1

# 3. 回归测试
node tests/smoke.test.mjs
node tests/recommend.test.mjs
node tests/integration.test.mjs
node tests/golden.test.mjs
node tests/flavor-matrix.mjs

# 4. 部署 AI 代理
cd ai-worker
wrangler secret put AI_KEY
wrangler deploy
```

测试全部是纯 Node 脚本，无测试框架依赖，克隆即可跑。

## 6. 哪些是 AI 写的，哪些不是

诚实说明，避免答辩时被问住：

| 类别 | 归属 |
| --- | --- |
| 前端代码、清洗脚本、测试用例 | AI 生成，人逐轮修改 |
| 推荐引擎的规则与权重 | 人定，AI 实现 |
| 数据采集与 OCR 清洗 | AI 写脚本，人跑、人核对 |
| 菜品数据的真实性 | 人（线下实拍 + 小程序接口） |
| 视频、文案、博客 | AI 起草，人改 |
| 什么时候该停、该换方案 | 人 |

最后一条是这份记录里最重要的一行。
