# 今天吃啥 · 开发日志 01 ⭐ 从一句 Prompt 到第一个上线项目
> ***v0.1*** ｜ 说一句偏好，替你把“今天吃啥”这顿定了。

项目英文名 What to Eat（仓库 what-to-eat，下文简称 wte）。正式中文名还在构思中，暂以“今天吃啥”相称。本文是 wte 开发日志系列的第一篇。

---
## 为什么做这个
“今天吃什么”大概是大学生每天回答次数最多、也最难回答的问题：档口几十个、菜品几百道，预算、口味、减肥计划全要在排队的三分钟里做完决策——多数时候干脆随便吃，吃完又后悔。

正好赶上传智杯 · 全国高校 Vibe Coding 开发挑战赛，我选了方向⑥（校园/垂直社区全栈 MVP 平台），决定把这个问题做成第一个真正意义上的项目：不是为比赛临时拼一个 demo，而是从一个真实痛点出发，持续迭代，也作为求职作品集的起点。

---
## 起点：一段原始 Prompt
Vibe Coding 的核心不是“让 AI 随便写”，而是把意图对齐做在前面。wte 的第一行代码来自这段 Prompt（原文保留，只把序号换成顿号，方便在不同预览器里看清）：

> 作为一个前端工程师，请帮我创建一个"今天吃啥"的移动端风格 Web 应用。要求：
>
> 1、页面简洁美观，有食欲感。  
> 2、顶部有一个输入框，用户可以输入自己的饮食偏好（如：减肥、预算15元、不想吃辣）。  
> 3、下方有一个显眼的"替我决定！"按钮。  
> 4、点击按钮后，从模拟的 50 道大学食堂菜品数据中，智能筛选并推荐一个菜品，并以卡片形式展示菜品名、价格、卡路里和推荐理由。

回头看，这段 Prompt 里有两个决定性的细节：

• 明确了输入形态——自然语言偏好，而不是表单勾选；  
• 明确了输出字段——菜名、价格、卡路里、推荐理由。  

后来的数据模型和推荐引擎，都是围绕这两点长出来的。
> 一句 Prompt 里写死的输入和输出，比后面补多少代码都管用。

---
## 三个关键设计决策
### 数据模型为推荐引擎服务
50 道菜不是随便列的清单。每道菜都带一组为“偏好匹配”设计的字段：口味标签、辣度分级（0–3）、是否素食、卡路里、价格，以及人气、低卡、性价比这类运营标签。“减肥”能不能命中低卡菜、“不想吃辣”能不能过滤干净，取决于字段设计得够不够细。

### 硬过滤 → 诚实放宽 → 加权随机
解析层用正则和关键词把“预算15元”“减肥”“不想吃辣”拆成结构化条件；硬过滤层先严格执行；筛完为空时，按热量 → 预算 → 素食 → 忌辣的顺序逐级放宽，并明确告诉你放宽了哪条。最后软打分取 top5 加权随机，在“懂你”和“不重样”之间找平衡。
> 宁可承认条件苛刻，也不静默塞一个不符的菜。

### 食欲感是第一生产力
一个帮你“决定吃什么”的工具，页面本身得让人饿。v0.1 用暖橙奶油色系打底，AI 生成的食堂质感插画做视觉锚点，楷体大标题压住气质，卡片出场和菜名轮换动效控制节奏；整体按移动端 430px 单列设计，并尊重系统的“减弱动态效果”偏好。

---
## 工程结构：零依赖，但留了后门
• 纯静态：HTML + CSS + 原生 JavaScript，5 个文件，零框架、零构建工具，双击 index.html 即可运行，任何人 clone 下来都能零成本复现。  
• 服务层 `api.js`：推荐服务单独成层，接口形状（入参 preferences，返回 dish / matched / reason / relaxed）完全按真实后端的标准设计，内部实现暂时是本地计算。  
• 两处细节：偏好草稿存 localStorage，刷新不丢；“换一个”通过 excludeIds 排除已推荐过的菜品。  

服务层里留了 TODO 替换点，**将来接后端时，前端其他文件一行不用动**。
> 零依赖不是省事，是把替换点提前画在图上。

---
## v0.1 的诚实局限
• 50 道菜全是模拟数据，卡路里按品类估算，不是真实营养值；  
• 没有真实档口信息，推荐无法回答“去哪个食堂哪个窗口”；  
• 纯前端，数据更新靠改代码。  
> 模拟数据能验证流程，验证不了推荐是否可信。

## 写在最后：1% 的灵感与 99% 的执行力
爱迪生说：“天才是 99% 的汗水加上 1% 的灵感。”放到今天，我想把它读成：**1% 的灵感，加上 99% 的执行力**。灵感负责回答“做什么、为什么做”，执行力负责把想法一步一步变成能跑的代码、能用的产品。

这一篇的 1%，是把“今天吃什么”从一句抱怨变成一句 Prompt：自然语言输入、四个输出字段。这两个决定后来长成了整个数据模型。

99% 的执行力，是给 50 道菜配上口味、辣度、素食、卡路里和运营标签，是硬过滤筛空后逐级放宽并明说放宽了哪条，也是零依赖的五个文件、430px 单列和一份可复现的协作记录。

v0.1 只有模拟数据，也没有档口信息。下一篇要把真实食堂的菜品搬进来。
