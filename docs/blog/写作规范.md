# 吃嘛 · 博客撰写规范

> 生效版本：v2.2.2 起。适用于 `docs/blog/` 下全部开发日志。

## 一、定位

工程日志，不是宣传稿。每篇只回答三件事：这一版做了什么、为什么这样做、哪里翻车了。

## 二、篇幅配比

| 成分 | 占比 | 说明 |
|---|---|---|
| 数据与结论 | 50–60% | 数字、表格、接口路径、对照结果 |
| 过程叙事 | 25–30% | 按时间顺序的动作与命令 |
| 情绪 | 10–15% | 只放在“翻车”和“收尾”两处 |

按全篇估算，不做逐句计量；比例是写作时的方向感，不是验收指标。

## 三、视角与人称

- 默认系统视角：主语是脚本、接口、数据、测试，不是“我”。
- 第一人称不硬性禁止，优先给两类节点：
  - **决策点**：在两个方案之间做选择的那一刻；
  - **翻车点**：判断错了、方案失败、数据打脸。
- 其余段落仍可用“我”，但不承担主语，也不写成大段自述。

## 四、每节收一句

- 除“先给结论”和“写在最后”之外，每个小节末尾给一句收束句。
- 用引用块单独成行，一句能脱离上下文站住的话。
- 不抒情，把该节的技术判断压成可摘录的短句。
- 不写“总之”“综上所述”“由此可见”。

示例：

> 分组列表一次返回，翻页翻不出没有的东西。

## 五、加粗落在判断上

- 加粗只包判断句，不包名词、数字、工具名。
- 反例：**Reqable**、**192 家店**
- 正例：**token 认人，不认学校**

## 六、图注写“看到了什么”

- 图注描述画面里的可观察事实，不写“我打开了什么”。
- 反例：图 1：我打开了 Reqable 抓包
- 正例：图 1：域名栏里 api-order.lcsw.cn 排在第一位

## 七、情绪的位置

- 只给“翻车”和“收尾”两处。
- 一句为限，不铺排形容词，不用连续感叹号。

## 八、结构与版本

- 标题：`吃嘛 · 开发日志 NN <副标题>`
- 开头：一句话摘要 + 元信息（版本 / 日期 / 工具 / 合规边界）
- 正文：编号小节，动作用动词开头
- 结尾：`1% 的灵感，加上 99% 的执行力`，结构沿用 01–05 篇——引句、这一篇的“1%”是什么判断、99% 对应的具体动作——但整体更短，不铺排
- 收尾落在一个没做完的具体动作上，不总结全文

## 九、避免

- 不用“首先 / 其次 / 最后”串段落
- 不写“赋能 / 闭环 / 生态 / 抓手”
- 数字必须能在仓库里复现，不能凭印象
